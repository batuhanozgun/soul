# PHASE GATE

A later SOUL development phase may not become active merely because work on it seems useful or urgent.

Before phase transition:

1. the current phase's active WP set must be completed or explicitly cancelled,
2. required verification must be current for the exact accepted artefacts,
3. required adversarial review must be complete,
4. unresolved findings must be repaired or explicitly accepted through the decision process,
5. `STATE.md` must be updated to the truth that will exist after transition,
6. any foundation or architecture decisions required by the completed phase must have the correct final status,
7. the next phase must begin with its own WP rather than an unbounded continuation of the previous chat.

Phase transitions are project-state changes, not conversational impressions.
