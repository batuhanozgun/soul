# SOUL VISION

SOUL exists to turn an intended outcome into a controlled working system capable of producing that outcome.

The user should not need to pre-design the agent organisation, workflow, memory scheme, toolchain, verification structure, or control system required by the work. SOUL must be able to determine what capabilities are needed, assemble or create the required working structure, execute the work through appropriately bounded agents and tools, preserve state outside model memory, verify what was actually done, and know when human judgement or approval is required.

SOUL is therefore not merely an agent runner, prompt collection, workflow template, software-development method, or fixed multi-agent team. It is intended to be a general-purpose agentic architecture that can create the task-specific operating system needed to pursue a goal.

A project may require software engineering, analytical decision support, research, design, operations, or capabilities that do not yet exist in the running system. Missing capability is not automatically a reason to fail or ask the user to design the solution. SOUL should be able to identify the missing capability, define it, research or construct it, isolate it, test it, independently verify it, and only then admit it into the working system when that is safe and justified.

The architecture must assume that LLM agents are fallible. Plausible language, tool success, another agent's agreement, remembered context, and an agent's own declaration of completion are not sufficient proof. Important state, authority, evidence, provenance, verification, policy, and completion conditions must live outside the model wherever practicable.

The target is not maximum autonomy. The target is the greatest useful autonomy that remains observable, bounded, recoverable, and appropriately governed by the human owner.
